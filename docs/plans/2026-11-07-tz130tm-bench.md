# TZ130TM Bench Firmware Implementation Plan

> Execute in this worktree after the user's approved scope; use the executing-plans workflow for implementation and verification.

**Goal:** Forward PC UART1 bytes unchanged to gimbal UART2 and print the approved status fields to PC.

**Architecture:** RX interrupts only fill the existing ring buffers. The foreground forwards small chunks using blocking UART writes, parses gimbal status continuously, and prints the latest newly received status at up to 5 Hz. No command decoding, coordinate checks, communication statistics, TX scheduler, link timeout, MAVLink output, or automatic laser commands.

**Tech Stack:** STM32F103C8T6 HAL, C11, CMake/Ninja/ARM GCC, standalone host C tests.

1. Add tests for unchanged forwarding, actual captured status, signed/scaled fields, partial/corrupt/short frames, and no autonomous commands. Observe missing behavior before implementing it.
2. Extend status decoding with self-test, framework roll, and three attitude angles. Add a small hardware-independent bench bridge and integer-based text formatting.
3. Wire the bridge inside CubeMX USER CODE blocks. Build only the bench modules, explicitly disable ID86/statistics, and generate HEX/BIN without a MAVLink dependency.
4. Run host checks and Debug/Release builds, review the diff, and deliver a short wiring/serial/flashing guide. Do not flash hardware or claim hardware validation.
